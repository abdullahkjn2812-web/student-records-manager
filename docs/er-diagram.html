Student Records Manager

Logical ER diagram | MongoDB + Mongoose | Abdullah Aslam
User / users
_id: ObjectId [PK]
name: String [required]
email: String [required, unique]
password: String [required]
role: String [admin | teacher]
createdAt: Date [automatic]
updatedAt: Date [automatic]
Role defaults to teacher.
Password hashing belongs to future auth.
No User relationship is defined in Week 2.
Student / students
_id: ObjectId [PK]
name: String [required]
rollNumber: String [required, unique]
className: String [required]
email: String [optional]
phone: String [optional]
createdAt: Date [automatic]
updatedAt: Date [automatic]
A student may have no marks records yet.
Marks / marks
_id: ObjectId [PK]
student: ObjectId [REF / FK*, required]
subject: String [required, trim, lowercase]
obtainedMarks: Number [required]
totalMarks: Number [required, > 0]
createdAt: Date [automatic]
updatedAt: Date [automatic]
UNIQUE (student, subject)
0 <= obtainedMarks <= totalMarks
One subject record per student.
Student 1 —— has —— 0..* Marks

ONE STUDENT, MANY SUBJECT RESULTS

Student._id is stored in Marks.student. Each Marks record belongs to exactly one student; a student can have zero or more marks records.

PK = primary identifier (_id)    REF / FK* = ObjectId reference    0..* = zero or many    unique = database unique index
* MongoDB references are not enforced foreign keys. Mongoose ref does not automatically check that the referenced student exists.
